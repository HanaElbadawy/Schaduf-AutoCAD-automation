# Stage 02 — Design Package Mapping

## Objective

Analyze a complete landscape design package provided as PDF documents and understand how the project is structured, organized, and divided into drawings, disciplines, sheets, and external references (Xrefs).

The goal is to create a reliable package mapping document that can guide future AutoCAD drawing production.

## Instructions

### 1. Review the Reference Package
- Read all provided PDF sheets and relevant project documents.
- Identify the project name, phases, disciplines, drawing numbers, and sheet titles where available.
- Review title blocks, legends, notes, drawing references, and revision information.
- Identify relationships between sheets.
- Do not assume missing information.

### 2. Analyze Sheet Organization
For each sheet, identify:
- Sheet number and title.
- Discipline or drawing category.
- Drawing purpose.
- Scale, if specified.
- Referenced drawings.
- Relevant legends and symbols.
- Revision information.
- Any special notes or requirements.

### 3. Identify Discipline Structure
Determine how the package is divided into disciplines and drawing groups.

Identify:
- Overall landscape plans.
- Hardscape plans.
- Softscape and planting plans.
- Grading and level plans.
- Setting-out plans.
- Details and sections.
- Other disciplines present in the supplied package.

Only include disciplines supported by the actual reference documents.

### 4. Map Xref Relationships
Analyze how drawings reference one another.

For each identified Xref, document:
- Referencing drawing.
- Referenced file or drawing.
- Purpose of the reference.
- Relevant discipline.
- Any visible layer or reference naming conventions.
- Whether the relationship is confirmed or inferred.

Do not invent missing Xref filenames or dependencies.

### 5. Propose Folder and File Structure
Based on the observed package, propose an organized project directory structure.

Consider:
- Project folders.
- Discipline folders.
- Drawing files.
- Xref files.
- PDF sheets.
- Details and supporting references.
- Shared resources.

Distinguish between:
- Structure explicitly observed in the reference package.
- Structure recommended for future organization.

Do not present recommendations as official SITES requirements unless documented.

### 6. Identify Naming Conventions
Extract the actual naming patterns used in the package.

Compare them with the official SITES naming standards.

Report:
- Confirmed naming rules.
- Observed naming practices.
- Inconsistencies.
- Missing information requiring clarification.

### 7. Prepare the Mapping Report
Create a structured report containing:

1. Project overview.
2. Sheet register.
3. Discipline breakdown.
4. Xref relationship map.
5. Proposed folder structure.
6. Naming convention analysis.
7. Identified inconsistencies.
8. Questions requiring clarification.

## Important Rules

1. Use only the supplied project documents and official standards.
2. Never invent drawing names, sheet numbers, or Xref dependencies.
3. Clearly distinguish observed facts from assumptions and recommendations.
4. Preserve the original project organization as evidence.
5. Do not modify original drawings during the analysis stage.

## Expected Output

A complete Design Package Mapping Report that explains the project structure, drawing relationships, Xref dependencies, naming conventions, and recommended folder organization.

The report must be detailed enough for another team member to understand how the package is organized and how future CAD production should follow it.
